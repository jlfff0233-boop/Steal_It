## [Enemy 상태 초기화 NullReferenceException]

* 발생 위치: Enemy.ChangeState / Enemy.Init / EnemySpawner.SpawnEnemy / PlayScene.Awake
* 증상: 플레이 시작 시 NullReferenceException 발생 / UI 갱신 이벤트 미연결 / Inventory 제출 후 Goal 점수 미반영 / Interact 아이템 제출 실패
* 원인: Enemy 상태 객체를 Awake에서 생성했지만 EnemySpawner가 Instantiate 직후 Init을 직접 호출함 / 비활성 스폰 포인트 하위에 생성되면 Awake가 보장되지 않은 상태에서 ChangeState가 먼저 실행될 수 있음
* 해결 방법: 상태 객체 생성 코드를 Enemy.Init 내부로 옮기고 ChangeState보다 먼저 실행한다.
* 추가 대응: PlayScene.Awake에서 이벤트 구독을 스폰보다 먼저 배치하면 스폰 쪽 예외가 UI/제출 이벤트 연결을 막는 위험을 줄일 수 있다.
* 확인 결과: 상태 객체 생성 순서 수정 후 UI 갱신과 제출 흐름 정상화 확인

## [PlayScene 초기화 중간 중단으로 이벤트 미구독]

* 발생 위치: PlayScene.Awake
* 증상: 아이템은 Inventory 딕셔너리에 들어가지만 UI가 갱신되지 않음 / 제출 시 Inventory는 비워지지만 Goal 점수가 오르지 않음
* 원인: Awake 초반의 스폰 처리에서 예외가 발생하면 그 아래의 Hero, Goal, SessionView 이벤트 구독 코드가 실행되지 않음
* 해결 방법: Hero 제출 이벤트 / Goal 점수 이벤트 / HeroModel UI 이벤트 구독을 스폰보다 먼저 실행한다.
* 주의: 입력이나 Canvas 문제가 아니라 이벤트 구독 자체가 실행되지 않는 경우 같은 증상이 나온다.

## [Interact 아이템 제출 실패]

* 발생 위치: Hero.SubmitInteractItem / Goal.SubmitInteractItem / PlayScene 이벤트 연결
* 증상: 들고 있는 Interact 아이템을 Goal에서 제출하려고 하면 제출되지 않고 내려놓기만 된 것처럼 보임
* 원인: PlayScene 이벤트 구독이 끊긴 상태에서는 OnInteractItemSubmitted를 발행해도 Goal.SubmitInteractItem이 호출되지 않음
* 해결 방법: PlayScene 이벤트 구독 정상 실행을 먼저 보장한다 / 이후 필요하면 SubmitInteractItem이 실제 제출 성공 여부를 기준으로 _holdItem을 비우도록 조정한다.

## [Inventory와 Interact 동시 제출 누락]

* 발생 위치: Hero.HandleSubmit
* 증상: Inventory 제출이 먼저 성공하면 Interact 아이템 제출이 실행되지 않음
* 원인: 제출 성공 시 바로 return하는 구조에서는 두 종류를 동시에 들고 있을 때 뒤쪽 제출 로직이 생략됨
* 해결 방법: Inventory 제출과 Interact 제출을 둘 다 시도한 뒤 둘 중 하나라도 성공하면 true를 반환한다.

## [DOTween destroyed Image 접근 오류]

* 발생 위치: DOTweenModuleUI.DOFillAmount / UnityEngine.UI.Image.fillAmount
* 증상: 아이템 박스 파괴 또는 아이템 드롭 후 DOTween이 이미 Destroy된 UI Image를 계속 갱신하려고 하며 경고 발생
* 원인: UI Image 대상 트윈이 살아 있는 상태에서 해당 Image 오브젝트가 먼저 제거됨
* 해결 방법: UI 오브젝트를 Destroy하기 전에 대상 트윈을 Kill한다 / 또는 OnDisable, OnDestroy에서 해당 Image 대상 Tween을 정리한다.
* 주의: Safe Mode가 경고로 잡아주더라도 남은 트윈이 계속 누적되면 다른 UI 갱신 문제로 이어질 수 있다.

## [ItemBox 정적 이벤트와 추격 재발]

* 발생 위치: ItemBox 정적 이벤트 / Enemy 이벤트 구독 / 추격 상태 전환
* 증상: 추격이 끝났는데 영역에 다시 들어가면 이전 추격 상황이 이어지는 것처럼 재개됨
* 원인 후보: 정적 이벤트 구독 해제가 누락되거나, 상자 피격/개봉 상태와 추격 트리거가 추격 종료 시점에 초기화되지 않음
* 해결 방법: 정적 이벤트는 OnEnable에서 구독하고 OnDisable에서 반드시 해제한다 / 추격 시작에 사용한 HitCount 또는 추격 트리거 상태는 추격 발생 후 명확히 소비 처리한다.
* 추가 대응: 같은 영역에 상자가 여러 개 있을 경우 어떤 상자의 이벤트인지 Enemy가 itemBox 매개변수로 범위 확인 후 처리한다.

## [상자 파괴 직후 패널티 회피]

* 발생 위치: ItemBox 파괴 / Item 드롭 / Enemy.CatchTarget / Hero.Caught
* 증상: 상자를 부순 직후 드롭된 아이템을 아직 먹지 않은 상태에서 잡히면 패널티가 없어 꼼수가 가능함
* 원인: 패널티 기준이 Inventory 보유 여부에만 묶여 있고, 상자 파괴로 발생한 위험 상태나 드롭 아이템 소유권은 반영되지 않음
* 해결 방법: 추격 중 상자 파괴 또는 개봉으로 생성된 아이템은 일정 시간 위험 상태로 관리한다 / 잡힘 처리에서 Inventory뿐 아니라 들고 있는 Interact 아이템 또는 최근 드롭 보상 상태까지 확인한다.

## [타이머 UI가 남은 시간이 아니라 진행 시간처럼 증가함]

* 발생 위치: PlayScene.UpdatePlayTime / PlaySceneView.UpdateRemainingTime
* 증상: 타이머 바 또는 시간 텍스트가 줄어드는 것이 아니라 점점 차오르거나 증가하는 것처럼 보임
* 원인: _playTime은 진행 시간이므로 계속 증가하는 값인데, UI 표시에서 playTime 자체를 분/초와 fillAmount 계산에 사용함
* 해결 방법: UI 표시 시 remainingTime = clearTime - playTime을 계산하고, 텍스트와 fillAmount 모두 remainingTime 기준으로 갱신한다.
* 확인 결과: 남은 시간 텍스트와 타이머 바가 감소 방향으로 표시되도록 수정됨

## [튜토리얼 적 상태 전환 오류]

* 발생 위치: TutorialDirector._tutorialEnemy / Enemy.Stunned / Enemy.ChangeState
* 증상: 튜토리얼 적이 아이템에 맞아 스턴 상태로 바뀌어야 할 때 상태 전환 오류가 발생함
* 원인: Enemy 상태 객체 배열은 Enemy.Init에서 생성되는데, 튜토리얼 적이 씬에 직접 배치되어 EnemySpawner.SpawnEnemy와 Init 흐름을 타지 않으면 _states가 비어 있는 상태로 ChangeState가 호출될 수 있음
* 해결 방법: TutorialDirector.Init에서 _tutorialEnemy.Init(hero)를 호출해 씬 배치 Enemy도 상태 객체 초기화를 보장한다.
* 현재 기준: PlayScene이 TutorialDirector.Init(_hero)를 호출하고, TutorialDirector가 튜토리얼 Enemy Init을 담당한다.
* 주의: 튜토리얼 적을 단순히 SetTutorialIdle(true)로 멈추는 것만으로는 상태 객체가 생성되지 않으므로 Init 호출은 유지해야 한다.

## [튜토리얼 적 Fall 애니메이션 잔류]

* 발생 위치: Enemy.SetTutorialIdle / Enemy.Update / Enemy.CheckIsGrounded
* 증상: 튜토리얼 적을 정지시켰는데 Idle이 아니라 Fall 애니메이션이 재생됨
* 원인: _isTutorialIdle이 true면 Enemy.Update가 바로 return하여 CheckIsGrounded가 실행되지 않음 / 정지 직전 IsGrounded가 false면 Animator가 Fall 조건을 유지함
* 해결 방법: SetTutorialIdle(true)에서 MoveSpeed 0, IsGrounded true, Idle 재생을 함께 처리한다.

## [튜토리얼 제출 점수 반영]

* 발생 위치: Hero 제출 이벤트 / PlayScene 제출 중재 / Goal.SubmitInventoryItem / Goal.SubmitInteractItem
* 증상: 튜토리얼에서 제출한 아이템 점수가 실제 현재 점수에 반영됨
* 원인: 튜토리얼 중에도 Hero 제출 이벤트가 Goal 제출 함수로 그대로 전달됨
* 해결 방법: PlayScene이 제출 요청 이벤트를 중재한다 / 튜토리얼 중 Inventory 제출은 점수 제출 요청을 생략한다 / 튜토리얼 중 Interact 제출은 item.Submit만 실행해 아이템 제거는 유지한다.

## [Cinemachine 카메라 연출 중 Hero 위치 복귀]

* 발생 위치: CameraCtrl / TutorialDirector.ShowMapCameraRoutine / CinemachineCamera.Follow
* 증상: 카메라가 포인트에서 포인트로 이동하지 않고 중간마다 Hero 쪽으로 돌아감
* 원인: Cinemachine이 Main Camera 위치를 계속 Hero Follow 기준으로 덮어쓰기 때문에 Transform 직접 이동 방식과 충돌함
* 해결 방법: Main Camera를 직접 움직이지 않고 CinemachineCamera.Follow 대상을 카메라 포인트 Transform으로 순서대로 변경한다 / 연출 종료 후 Follow 대상을 Hero로 복구한다.

## [Unity Inspector MissingReferenceException]

* 발생 위치: UnityEditor.EditorGUI / InspectorWindow / TutorialDirector, TutorialView, UnityEngine.UI.Image 표시
* 증상: 이미 Destroy된 TutorialDirector, TutorialView, Image를 Inspector가 계속 접근했다는 MissingReferenceException 발생
* 원인 후보: Play 중 스크립트 컴파일 / Inspector Lock / 삭제된 런타임 오브젝트 선택 유지 / 스크립트 파일 삭제 후 재생성으로 에디터 참조가 꼬임
* 해결 방법: 파일 삭제 후 재생성 방식 금지 / Play 중 스크립트 수정 지양 / Inspector Lock 해제 / 살아 있는 오브젝트 선택 후 Console Clear / 반복 시 Unity 재시작
* 주의: 스택에 사용자 스크립트 호출이 없고 UnityEditor Inspector 호출만 있으면 런타임 로직 오류보다 에디터 참조 꼬임으로 먼저 판단한다.

## [튜토리얼 선행 행동 미인식]

* 발생 위치: TutorialDirector.Jumped / FastFalled / Dashed / Attacked / OnItemCollected / HoldItem / PutDownItem / ThrownItem / Submit 이벤트 처리
* 증상: 튜토리얼 안내 단계보다 먼저 행동을 해버리면, 나중에 해당 단계가 와도 이미 한 행동이 인정되지 않아 진행이 막힘
* 원인: 각 행동 함수가 현재 단계가 아니면 return하면서 선행 행동 이벤트를 버림
* 해결 방법: 행동 완료 여부를 bool로 저장한다 / ChangeStep 이후 현재 단계가 이미 완료된 행동이면 다음 행동 단계로 넘긴다.
* 주의: 미리 수행한 단계는 안내가 뜨자마자 넘어갈 수 있음 / 막힘 방지를 우선한 처리이다.

* Console 첫 에러 위치 확인
* PlayScene.Awake가 끝까지 실행됐는지 확인
* 이벤트 구독 코드가 스폰이나 예외 발생 코드보다 뒤에 있는지 확인
* 정적 이벤트가 OnEnable과 OnDisable에서 짝을 맞춰 구독/해제되는지 확인
* 제출 실패 시 Hero 이벤트 발행과 Goal 구독이 둘 다 존재하는지 확인
* 투사체가 이동하지 않으면 Enemy.Attack에서 Projectile.Init 호출 여부와 Projectile 이동 방식 확인
* 타이머 표시가 증가하면 UI에서 playTime이 아니라 clearTime - playTime을 표시하는지 확인
* 점수가 중복 반영되면 SubmitInventoryItem 같은 제출 함수가 한 입력에서 두 번 호출되는지 확인
* 불러오기 후 튜토리얼 UI가 뜨면 SaveManager.HasSaveData 확인 / TutorialDirector.Init 스킵 분기 진입 여부 확인 / _isRunning false 상태에서 ChangeStep이 차단되는지 확인
* 튜토리얼에서 먹은 아이템 수가 누적 획득 수에 반영되면 PlayScene.AddCollectedItemCount가 _isTutorialRunning을 확인하는지 먼저 확인
